# 串口桥接协议

本文档描述上位机 `stm32_robot_bridge` 当前实现的 STM32 上位机 v2 协议。协议权威来源是下位机源码：

- `D:\Document\Work\projects\F407_V2.0\App\protocol\upper_protocol.h`
- `D:\Document\Work\projects\F407_V2.0\App\protocol\upper_protocol.c`
- `D:\Document\Work\projects\F407_V2.0\App\protocol\upper_uart.c`

## 1. 物理层

| 参数 | 值 |
|------|-----|
| 接口 | Raspberry Pi GPIO UART |
| 默认设备 | `/dev/serial0`（实际通常指向 `/dev/ttyAMA0`） |
| 波特率 | 115200 |
| 数据格式 | 8N1 |
| 电平 | 3.3V TTL |
| 接线 | Pi TX -> STM32 PD9 / USART3_RX；Pi RX <- STM32 PD8 / USART3_TX；必须共地 |

正式默认不扫描 USB 串口；临时调试可显式传入其他 `port`。

## 2. 帧格式

```text
0xA5 0x5A + Length(1B) + Cmd(1B) + Payload(0..64B) + CRC8(1B)
```

- `Length` 是 `Cmd + Payload` 的字节数，不是单独 payload 长度。
- 最大 payload 为 64B，最大 `Length` 为 65。
- CRC8 初值 0，覆盖 `Length + Cmd + Payload`；逐位左移，最高位为 1 时异或 `0x5E`。
- 解析器必须支持分包、粘包、垃圾字节和 CRC 错误后重新找帧头；不完整尾部数据必须保留。

## 3. 命令

| Cmd | 名称 | 方向 | Payload |
|-----|------|------|---------|
| `0x01` | `SET_VELOCITY` | 上位机 -> 下位机 | 10B |
| `0x02` | `ESTOP` | 上位机 -> 下位机 | 1B |
| `0x03` | `LINE_CTRL` | 上位机 -> 下位机 | 1B |
| `0x81` | `STATUS` | 下位机 -> 上位机 | 64B |

### SET_VELOCITY

```text
float linear_x
float angular_z
uint8 enable
uint8 mode
```

小端序。上位机发送 `mode=2`，但不再用该字段判断下位机控制状态。`enable=1` 表示上位机控制源有效；`enable=0` 表示释放上位机控制源。

`/cmd_vel` 超时后，bridge 只发送一次 `linear=0, angular=0, enable=0`，之后不再周期占用 `CONTROL_SOURCE_UPPER`。

### ESTOP

```text
uint8 enabled
```

- `1`: 触发急停。
- `0`: 解除急停。

正常停车、节点退出、串口重连不发送 ESTOP，只尽力发送一次 `SET_VELOCITY(enable=0)`。急停必须通过 `/chassis/estop` 显式触发或解除。

### STATUS

下位机每 50ms 主动上报，约 20Hz。上位机不发送状态请求。

| 偏移 | 字段 | 类型 | 单位/说明 |
| -: |------|------|-----------|
| 0 | version | uint8 | 必须为 2 |
| 1 | status_flags | uint8 | bit0 急停；bit1 fault-stop；bit2 巡线；bit3 全部速度有效 |
| 2 | control_source | uint8 | 0 none，1 upper，2 PS2，3 ESP12F，4 debug，5 line |
| 3 | motor_enabled_mask | uint8 | M1~M4 启用位 |
| 4 | error_flags | uint32 | 当前错误 |
| 8 | latched_error_flags | uint32 | 锁存错误 |
| 12 | battery_mv | uint16 | mV |
| 14 | motor_speed_mmps[4] | int16[4] | mm/s |
| 22 | encoder_count[4] | int32[4] | 累积计数 |
| 38 | motor_current_ma[4] | uint16[4] | mA |
| 46 | motor_target_mmps[4] | int16[4] | mm/s |
| 54 | motor_output_permille[4] | int16[4] | permille |
| 62 | motor_speed_valid_mask | uint8 | 每电机速度有效位 |
| 63 | reserved | uint8 | 忽略 |

非 64B STATUS 或 version 非 2 的 STATUS 直接丢弃并记录警告。

## 4. 四路聚合与里程计

电机语义：

- M1、M2 为左侧。
- M3、M4 为右侧。
- 当前默认两驱为 M2 左、M3 右，即 `enabled_mask=0b0110`。

聚合规则：

- 左侧 mask: `enabled_mask & 0b0011`。
- 右侧 mask: `enabled_mask & 0b1100`。
- 每侧速度和目标速度为已启用电机平均值。
- 每侧编码器计数为已启用电机平均值，仅用于诊断展示。
- 每侧电流为已启用电机电流求和。
- 任一侧无启用电机，或任一已启用电机速度无效，本帧 odom 不可信。

里程计速度：

```text
vx = (left_speed + right_speed) / 2
wz = (right_speed - left_speed) / wheel_track_width
```

默认参数：

| 参数 | 默认值 |
|------|--------|
| `wheel_track_width` | `0.1780` |
| `wheel_radius` | `0.0350` |
| `status_timeout` | `0.75` |
| `cmd_timeout` | `0.25` |
| `drive_keepalive_sec` | `0.10` |

`wheel_radius` 当前不参与 odom 积分，因为 MCU 已上报 m/s 轮速，但仍保持真实值，避免后续误用旧参数。

## 5. ROS2 接口

订阅：

| 话题/服务 | 类型 | 说明 |
|-----------|------|------|
| `/cmd_vel` | `geometry_msgs/Twist` | 速度命令 |
| `/chassis/estop` | `std_srvs/SetBool` | `true` 触发急停，`false` 解除急停 |

发布：

| 话题 | 类型 | 说明 |
|------|------|------|
| `/odom` | `nav_msgs/Odometry` | wheel-only 里程计 |
| `/tf` | TF | 未启用 EKF 时由 bridge 发布 `odom -> base_link` |
| `/chassis/status` | `std_msgs/UInt32` | `error_flags` |
| `/battery_state` | `sensor_msgs/BatteryState` | 电池电压 |
| `/motor/left_current` | `std_msgs/Float32` | 左侧聚合电流 |
| `/motor/right_current` | `std_msgs/Float32` | 右侧聚合电流 |

当前 v2 STATUS 不包含 IMU，bridge 不发布伪造 IMU 数据。若启用 wheel-only EKF，bridge 关闭 TF，由 EKF 发布 `odom -> base_link`。

## 6. 诊断日志

`status_summary` 至少包含：

- protocol version
- control_source
- status_flags
- enabled mask
- speed-valid mask
- battery
- error_flags
- latched_error_flags

推荐实机检查：

```bash
./launch_scripts/check_chassis.sh
ros2 topic hz /odom
ros2 service call /chassis/estop std_srvs/srv/SetBool "{data: true}"
ros2 service call /chassis/estop std_srvs/srv/SetBool "{data: false}"
```
