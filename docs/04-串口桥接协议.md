# 串口桥接协议

本文档描述上位机 `stm32_robot_bridge` 当前实现的 STM32 上位机 v2 协议。协议权威来源是下位机仓库 [Yaoser-x/SlamRobot_Chassis_Control](https://github.com/Yaoser-x/SlamRobot_Chassis_Control) 的：

- `Domain/protocol/upper_protocol.h`
- `Domain/protocol/upper_protocol.c`
- `Service/communication/upper_uart_service.c`

## 1. 物理层

| 参数 | 值 |
|------|-----|
| 接口 | Raspberry Pi GPIO UART |
| 默认设备 | `/dev/serial0`（实际通常指向 `/dev/ttyAMA0`） |
| 波特率 | 115200 |
| 数据格式 | 8N1 |
| 电平 | 3.3V TTL |
| 接线 | Pi TX -> STM32 PD9 / USART3_RX；Pi RX <- STM32 PD8 / USART3_TX；必须共地 |

正式默认不扫描 USB 串口；临时调试可显式传入其他 `port`。

## 2. 帧格式

```text
0xA5 0x5A + Length(1B) + Cmd(1B) + Payload(0..99B) + CRC8(1B)
```

- `Length` 是 `Cmd + Payload` 的字节数，不是单独 payload 长度。
- 最大 payload 为 99B，最大 `Length` 为 100。
- CRC8 初值 0，覆盖 `Length + Cmd + Payload`；算法与下位机 `UpperProtocol_Checksum8()` 的 256 项查表实现完全一致（每字节执行 `crc = table[crc ^ byte]`）。
- 解析器必须支持分包、粘包、垃圾字节和 CRC 错误后重新找帧头；不完整尾部数据必须保留。

## 3. 命令

| Cmd | 名称 | 方向 | Payload |
|-----|------|------|---------|
| `0x01` | `SET_VELOCITY` | 上位机 -> 下位机 | 10B |
| `0x02` | `ESTOP` | 上位机 -> 下位机 | 1B |
| `0x03` | `LINE_CTRL` | 上位机 -> 下位机 | 1B |
| `0x04` | `CLEAR_FAULT` | 上位机 -> 下位机 | 0B |
| `0x81` | `STATUS` | 下位机 -> 上位机 | 65B |
| `0x82` | `DIAGNOSTIC` | 下位机 -> 上位机 | 28B |
| `0x83` | `IMU_STATUS` | 下位机 -> 上位机 | 99B |

### SET_VELOCITY

```text
float linear_x
float angular_z
uint8 enable
uint8 mode
```

小端序。上位机发送 `mode=2`，但不再用该字段判断下位机控制状态。`enable=1` 表示上位机控制源有效；`enable=0` 表示释放上位机控制源。

`/chassis/command` 明确释放或超时后，bridge 发送 `linear=0, angular=0, enable=0`，之后不再周期占用 `CONTROL_SOURCE_UPPER`。

### ESTOP

```text
uint8 enabled
```

- `1`: 触发急停。
- `0`: 下位机仅接受本地 USART1 控制台解除急停；远程 `0x00` 不产生解除效果（详见下位机 `upper-protocol-v2.md`）。上位机 bridge 会直接拒绝 `/chassis/estop false`，不发送会被忽略的帧。

正常停车、节点退出、串口重连不发送 ESTOP，只尽力发送一次 `SET_VELOCITY(enable=0)`。急停必须通过 `/chassis/estop` 显式触发。

### CLEAR_FAULT

Payload 为空，用于请求下位机清除可恢复的锁存故障。bridge 通过 `/chassis/clear_fault`（`std_srvs/Trigger`）服务入口暴露。

> **注意**：CLEAR_FAULT 不能解除急停；急停解除仅限本地 USART1 控制台。

### DIAGNOSTIC

下位机每 200ms 主动上报诊断帧（POST 结果、ADC 状态、任务超时、IMU 质量、复位原因、运行时间）。

| 偏移 | 字段 | 类型 | 说明 |
| -: |------|------|------|
| 0 | protocol_version | uint8 | 必须为 2 |
| 1 | schema_version | uint8 | 当前为 1 |
| 2 | post_done | uint8 | POST 自检完成标志 |
| 3 | imu_status_flags | uint8 | IMU 状态标志 |
| 4 | post_error_flags | uint32 | POST 错误位掩码 |
| 8 | adc_invalid_reason_flags | uint32 | ADC 无效原因 |
| 12 | task_timeout_mask | uint16 | bit0=safety, bit1=motor, bit2=RPI, bit3=IMU, bit4=LINE, bit5=ESP, bit6=PS2, bit7=LED, bit8=OLED |
| 14 | reserved | uint16 | 保留（必须为 0） |
| 16 | imu_quality_flags | uint32 | IMU 质量标志 |
| 20 | reset_reason_flags | uint32 | 启动时捕获的 RCC 复位标志 |
| 24 | uptime_ms | uint32 | 运行时间（ms） |

bridge 将 `post_error_flags` 发布到 `/chassis/diagnostic`，并对 POST 失败、ADC 异常、任务超时记录 WARN 日志。

### STATUS

下位机每 50ms 主动上报，约 20Hz。上位机不发送状态请求。

| 偏移 | 字段 | 类型 | 单位/说明 |
| -: |------|------|-----------|
| 0 | version | uint8 | 必须为 2 |
| 1 | status_flags | uint8 | bit0 急停；bit1 fault-stop；bit2 巡线；bit3 全部速度有效 |
| 2 | control_source | uint8 | 0 none，1 upper，2 PS2，3 ESP12F，4 debug，5 line |
| 3 | motor_enabled_mask | uint8 | M1~M4 启用位 |
| 4 | error_flags | uint32 | 当前错误 |
| 8 | latched_error_flags | uint32 | 锁存错误 |
| 12 | battery_mv | uint16 | mV |
| 14 | motor_speed_mmps[4] | int16[4] | mm/s |
| 22 | encoder_count[4] | int32[4] | 累积计数 |
| 38 | motor_current_ma[4] | uint16[4] | mA |
| 46 | motor_target_mmps[4] | int16[4] | mm/s |
| 54 | motor_output_permille[4] | int16[4] | permille |
| 62 | motor_speed_valid_mask | uint8 | 每电机速度有效位 |
| 63 | encoder_anomaly_mask | uint8 | 每电机编码器异常位 |
| 64 | comm_health_flags | uint8 | CRC/超时/发送丢弃等通信健康标志 |

非 65B STATUS 或 version 非 2 的 STATUS 直接丢弃并记录警告。

### IMU_STATUS

下位机在 BMI270 在线时主动上报独立 IMU 帧。bridge 将其转换为 `sensor_msgs/Imu` 发布到 `/imu/data`，默认 `frame_id=imu_link`；不发布伪造 IMU。

| 偏移 | 字段 | 类型 | 单位/说明 |
| -: |------|------|-----------|
| 0 | version | uint8 | 必须为 2 |
| 1 | accel_g[3] | float[3] | g，bridge 转为 m/s^2 |
| 13 | gyro_corrected_dps[3] | float[3] | deg/s，bridge 转为 rad/s |
| 25 | euler_deg[3] | float[3] | deg，仅用于诊断，不进入 `sensor_msgs/Imu` |
| 37 | quaternion[4] | float[4] | 线上顺序 w/x/y/z，bridge 解码时重映射为 x/y/z/w 再归一化发布 |
| 53 | timestamp_ms | uint32 | 下位机毫秒时间 |
| 57 | sensor_time | uint32 | BMI270 sensor time |
| 61 | sample_count | uint32 | IMU 样本计数 |
| 65 | quality_flags | uint32 | IMU 质量标志 |
| 69 | quality_counters[7] | uint32[7] | SPI/init/FIFO/timestamp/saturation/anomaly/attitude 计数 |
| 97 | status_flags | uint8 | bit0 online；bit1 calibrated；bit2 error；bit3 sensor_time_valid |
| 98 | temperature_c | int8 | 摄氏度 |

非 99B IMU_STATUS、version 非 2、或非法四元数不会影响 `/odom`；非法四元数时 orientation covariance[0] 置为 -1。

## 4. 四路聚合与里程计

电机语义：

- M1、M2 为左侧。
- M3、M4 为右侧。
- 当前默认两驱为 M2 左、M3 右，即 `enabled_mask=0b0110`。

聚合规则：

- 左侧 mask: `enabled_mask & 0b0011`。
- 右侧 mask: `enabled_mask & 0b1100`。
- 每侧速度和目标速度为已启用电机平均值。
- 每侧编码器计数为已启用电机平均值，仅用于诊断展示。
- 每侧电流为已启用电机电流求和。
- 任一侧无启用电机、任一已启用电机速度无效，或已启用电机出现编码器异常，本帧 odom 不可信。

里程计速度：

```text
vx = (left_speed + right_speed) / 2
wz = (right_speed - left_speed) / wheel_track_width
```

默认参数：

| 参数 | 默认值 |
|------|--------|
| `wheel_track_width` | `0.1760` |（机械实测 181.5mm，有效轮距 ~176mm）|
| `wheel_radius` | `0.0350` |（轮径 70mm）|
| `drive_mode` | `differential` |
| `imu_topic` | `/imu/data` |
| `imu_frame_id` | `imu_link` |
| `status_timeout` | `0.25` |
| `cmd_timeout` | `0.15` |
| `drive_keepalive_sec` | `0.05` |
| `hard_max_linear_mps` | `0.45` |
| `hard_max_angular_radps` | `1.50` |
| `max_command_age_sec` | `0.15` |
| `odom_max_dt_sec` | `0.25` |
| `imu.use_orientation` | `false` |
| `imu.angular_velocity_stddev.{x,y,z}` | `0.02` |
| `imu.linear_acceleration_stddev.{x,y,z}` | `0.2` |

`wheel_radius` 当前不参与 odom 积分（因为 MCU 已上报 m/s 轮速），但仍保持真实值避免后续误用。有效轮距 0.176m 小于机械轮距 181.5mm，用于补偿轮胎变形和接触面偏移。

里程计只在收到新的合法 STATUS 时积分一次，采样时间使用主机 monotonic 接收时间；首帧、重复/倒退时间戳以及超过 `odom_max_dt_sec` 的通信间隙都不补积分。

可信帧的协方差不是固定常数：线速度方差随 `|vx|`、`|wz|`、`dt` 和左右轮速度分歧增大，角速度方差随 `|wz|`、`|vx|` 和左右轮分歧增大。STATUS 过期、ESTOP/fault-stop、编码器异常或过大采样间隙时直接发布不可信协方差。模型初值记录在 `robot_bringup/config/robot_calibration.yaml`，实车数据完成后应替换保守初值。

运动学聚合模型通过 `drive_mode` 参数选择。当前仅实现 `differential`（两轮差速），物理接线仍固定为 M1+M2 左侧、M3+M4 右侧。未来扩展四轮差速、麦轮等其他驱动模式时，需在 `aggregate_status()` 中增加对应模型，并同步更新测试和本文档。

## 5. ROS2 接口

订阅：

| 话题/服务 | 类型 | 说明 |
|-----------|------|------|
| `/chassis/command` | `robot_interfaces/ChassisCommand` | robot_control 输出的显式底盘控制命令 |
| `/chassis/estop` | `std_srvs/SetBool` | `true` 触发急停；`false` 返回失败，解除仅限本地 USART1 控制台 |
| `/chassis/clear_fault` | `std_srvs/Trigger` | 请求下位机清除可恢复锁存故障 |
| `/chassis/line_ctrl` | `std_srvs/SetBool` | 启用/禁用巡线模式 |

发布：

| 话题 | 类型 | 说明 |
|------|------|------|
| `/wheel/odom` | `nav_msgs/Odometry` | wheel-only 里程计 |
| `/tf` | TF | 仅兼容模式下由 bridge 发布；实车默认由 EKF 独占 `odom -> base_link` |
| `/chassis/status` | `std_msgs/UInt32` | `error_flags` |
| `/chassis/diagnostic` | `std_msgs/UInt32` | DIAGNOSTIC 帧的 `post_error_flags` |
| `/chassis/state` | `robot_interfaces/ChassisState` | bridge 状态、命令来源/sequence 与固件控制源 |
| `/diagnostics` | `diagnostic_msgs/DiagnosticArray` | serial、protocol、control、chassis、imu 标准诊断 |
| `/battery_state` | `sensor_msgs/BatteryState` | 电池电压 |
| `/motor/left_current` | `std_msgs/Float32` | 左侧聚合电流 |
| `/motor/right_current` | `std_msgs/Float32` | 右侧聚合电流 |
| `/imu/data` | `sensor_msgs/Imu` | BMI270 IMU_STATUS 转换后的 IMU 数据 |

IMU 发布只来自下位机 `IMU_STATUS`。实车默认启用 `robot_localization`：wheel odom 只贡献 `vx`，IMU 只贡献 `gyro_z`；bridge 关闭 TF，由 EKF 独占发布 `/odom` 和 `odom -> base_link`。

IMU 消息时间使用 MCU `timestamp_ms` 经偏移低通映射到 ROS 时间；`sample_count` 用于检测重复、丢样、uint32 回绕和 MCU 重启。默认不发布 orientation（协方差首项为 `-1`），只为角速度与线加速度填入保守初值协方差；这些初值必须由静态采集和 Allan 分析替换。

## 6. 诊断日志

`status_summary` 至少包含：

- protocol version
- control_source
- status_flags
- enabled mask
- speed-valid mask
- battery
- error_flags
- latched_error_flags

推荐实机检查：

```bash
./launch_scripts/check_chassis.sh
ros2 topic hz /wheel/odom
ros2 topic echo /imu/data --once
ros2 service call /chassis/estop std_srvs/srv/SetBool "{data: true}"
ros2 service call /chassis/estop std_srvs/srv/SetBool "{data: false}"
ros2 service call /chassis/clear_fault std_srvs/srv/Trigger
ros2 service call /chassis/line_ctrl std_srvs/srv/SetBool "{data: true}"
```
