# v0.5.0-rc1 发布候选

v0.5.0-rc1 将 ROS Platform API 升级为 v4，同时保持下位机 Upper Protocol v3 字节协议不变。该版本明确区分 Host 候选命令与整车最终仲裁，按 `motor_enabled_mask` 消费 M2+M3 默认两驱观测，并引入跨机会话恢复、导航保护和配置身份门禁。

固定候选基线为上位机 `0d91f9e5f04350a64e50f9b509de8998cf4f36c0` 与下位机 `366a0385290d526009e6cd3bbdaa7b74b2fecad6`。开发提交建立在该上位机基线上；最终发布证据必须记录实际待发布提交。

当前状态为 **BLOCKED**：真实 UART HIL、固件参数 CRC、实车验收、底盘动态测试和最终标定均未完成，`release_compatible` 必须保持 `false`。

升级前应刷入候选下位机，生成并核对标定包，完成 `verification/reports` 中 v0.5.0-rc1 的全部机器报告，再执行 `python3 scripts/verify/verify_release.py`。回滚必须整体回滚到一组已验证的上、下位机版本，禁止把 Platform API 4 与旧 ROS 接口混用。
