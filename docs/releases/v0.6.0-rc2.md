# v0.6.0-rc2 上位机发布候选

rc2 在 Platform API 5 上收口 Host 命令、Bridge 会话、正式里程计、IMU、配置编译和验证证据。不修改 Upper Protocol v3 字节语义。

代码边界固定为：`robot_control` 只仲裁 Host 候选和 Host rearm；`robot_supervision` 只给出运动一致性风险与降级建议；Bridge 只拥有 transport/codec/session/ACK/状态适配；正式 wheel odom、IMU 质量、融合和唯一 `odom -> base_link` 所有权归 `robot_state_estimation`；固件继续拥有最终物理来源仲裁、运动许可和电机输出。

rc2 已实现并自动测试非法候选隔离、显式 Bridge 决策、DDS 新鲜度、Upper v3
交叉向量、PTY、科学化 wheel odom/协方差、严格配置编译和扩展 Fake Base；同时提供
IMU Allan、EKF A-D、运动风险 ROC、SLAM 和 Nav2 的实验定义与分析工具。后几项的
机器报告仍为 `NOT_RUN`，不能把“具备工具”表述为“实验已完成”。物理证据必须按
UART HIL → 架空轮 → 低速实车 → 标定 → SLAM/Nav2 的顺序补齐。

下位机候选固定为 `bc472cc874e930aaed6eb8e7de73b41a2563dd85` / `v1.0.0-rc1`，但在 UART HIL、参数 CRC、硬件版本和实车证据齐全前，`release_compatible` 必须保持 `false`。

回滚必须整体回滚上下位机和有效配置，不得混用未经验证的 commit、参数 CRC 或标定包。

发布身份不得在提交中自引用自身 SHA。HIL 前先冻结 `release_candidate_commit`，完成全部测试后将同一 SHA 写入 `tested_commit`；所有报告引用该测试代码提交。证据汇总提交和最终 tag 通过兼容清单关联到被测试代码，不把证据提交误称为已经执行过 HIL 的代码提交。

正式 odom/TF 出口固定为 `formal_odometry`。默认 wheel-only；wheel+IMU 仅是实验
模式。配置 schema 使用 Draft 7，以兼容 ROS Humble 的 jsonschema 3.x 运行环境。
