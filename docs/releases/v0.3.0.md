# v0.3.0 发布候选说明

当前状态：**Release candidate，硬件门未执行，不得打正式 tag。**

## 兼容组合

- 上位机：ARM 分支，Platform API 2，基线 `2c9718e7`。
- 下位机：`v1.0.0-beta4@a4ae10d5`，upper protocol v2。
- 固件 UPPER 实际超时为 200 ms；历史 500 ms chassis timeout 宏不是当前 UPPER 契约。

## 升级

1. 锁定上下位机提交，核对 `compatibility/firmware.yaml`。
2. 刷入指定固件，架空车轮并保持 ESTOP 可用。
3. 执行 `scripts/verify/verify_upper.sh`。
4. 把研究/自定义速度源改为 `/cmd_vel/research/<name>` 并在 mux 白名单登记；不再直接向 bridge 发裸 `Twist`。
5. 验证 `/chassis/command` 含显式 `enable/source/sequence`，bridge 进入 READY 前不发 `enable=1`。
6. 按 `reports/hil/v0.3.0.md` 和 `reports/vehicle/v0.3.0.md` 完成实物验收，最后执行 `python3 scripts/verify/verify_release.py`。

## 回滚

1. ESTOP，断开电机供电，保留本次日志和 bag。
2. 同时回滚到上一个已验证的上位机 tag 和其兼容矩阵指定的固件，禁止混用 API 1/2。
3. 恢复该 tag 对应的参数和标定文件，重新构建。
4. 架空车轮重做方向、超时释放、ESTOP 和串口断开测试，通过后才落地。

## 已知限制

- protocol v2 无命令应用回执和 STATUS MCU 采样时间；sequence/MCU timestamp 需升级 v3。
- 当前标定、IMU Allan、HIL、SLAM 和 Nav2 报告仍为 NOT_RUN/临时值，因此 v0.3.0 仍是候选版。
- 裸 `/cmd_vel/driver` 只是显式开关控制的迁移兼容面，下一主版本移除。
