# 建图指南

当前默认是 lidar + wheel-only。真实底盘建图必须在 Gate D（UART HIL、几何、雷达
yaw、IMU 时间链、TF 唯一性）后进行；Gate 前用 Fake Base 验证编排。

## 启动

```bash
# 软件链路
./bin/robot mapping lidar quality --manual --fake-base --rviz

# Gate D 后的受控实车
./bin/robot mapping lidar quality --manual --real-base --rviz

# 保存地图
./bin/robot save-map my_map
```

`quality` 是 provisional 基线；`precision` 和 `fast` 是实验 overlay，不表示已经通过
CPU、闭环或地图质量验收。`--ekf-base` 只用于正式 A/B Bag 设计，不是推荐建图默认。

## 运行链

```text
YDLidar -> scan_raw -> scan_normalizer -> scan -> slam_toolbox -> map
Base provider -> WheelObservation -> wheel_odometry -> wheel/odom
              -> ImuObservation   -> imu_adapter    -> imu/data
wheel/odom (or explicit internal EKF) -> formal_odometry -> odom + TF
```

`base_link -> laser_frame` 由 robot description 发布。Bridge、Fake Base、wheel odom
和内部 EKF 都不发布正式 TF。

## 雷达配置

正式基线来自 `src/robot_config/config/components/lidar.yaml`，默认 `/dev/ydlidar`、
`inverted: true`、`reversion: false`。运行时可临时诊断：

```bash
./bin/robot mapping lidar --fake-base --no-lidar-inverted
./bin/robot mapping lidar --fake-base --lidar-reversion
./bin/robot mapping lidar --fake-base --lidar-yaw-deg 90
```

临时覆写必须记录在 run manifest；确定的外参应回填 calibration，而不是长期依赖 CLI。

## 无底盘模式

`base_mode:=none` 仅用于 mapping，可由 bringup 发布静态
`odom -> base_link` 回退。它只能检查雷达/SLAM，不能作为 odom、TF 动态质量或导航
证据。旧 `auto_mapping_drive` 已被代码拒绝，frontier explorer 只存在于 legacy。

## SLAM 实验

实验定义：`verification/configs/experiments/slam-sweep-v0.6.0-rc2.yaml`。

- 训练集：`bag_06_mapping_train`
- 独立验证集：`bag_07_mapping_validation`
- 验证集禁止继续调参
- 地图截图不是验收证据
- 必填闭环位置/角度、墙体重影、假回环、节点数、CPU、内存、TF 延迟和 scan drop

当前 definition 状态为 `dataset_pending`，所以参数值只能称 provisional/experimental。
完整录制步骤见 [建图测试流程](./05-建图测试流程.md)。
