# 快速开始

本文对应 Platform API 5 / Upper v3 / `v0.6.0-rc2`。用户入口为 `bin/robot`；
`system.launch.py` 是工程编排入口，真实/Fake Base 直接调用时仍必须提供编译后的
effective params。

> 当前真实底盘发布门关闭。候选固件固定为
> `bc472cc874e930aaed6eb8e7de73b41a2563dd85`，但参数 CRC、硬件 revision、UART
> HIL、正式标定和车辆证据尚未记录。以下真实底盘命令用于完成相应 Gate，不表示
> 已获准无人看护运行。

## 1. 环境与构建

要求 Ubuntu 22.04 arm64、ROS 2 Humble、Python 3.10，用户属于 `dialout` 组。

```bash
cd /home/robot/ros2_ws
source /opt/ros/humble/setup.bash
./scripts/bootstrap/fetch_vendor.sh
sudo ./scripts/bootstrap/install_ydlidar_sdk.sh
./scripts/build/build_ros_ws.sh
source install/setup.bash
```

默认设备为底盘 `/dev/serial0`、雷达 `/dev/ydlidar`。底盘 `auto` 模式已废弃；
不得让底盘和雷达解析到同一串口。

## 2. 软件/Fake Base 验证

在物理 Gate 前优先运行：

```bash
./bin/robot mapping lidar --manual --fake-base --no-rviz
./bin/robot check lidar
./bin/robot check mapping --allow-headless
```

Fake Base 明确发布 `simulated: true`，验证 Platform API、状态估计、监督和 SLAM
编排，但不能替代 UART HIL、停车时间或车辆报告。

## 3. 受控真实底盘验证

仅在 UART HIL、参数 CRC、ESTOP/fault/rearm 已通过，且电机断动力或架空轮时执行：

```bash
./bin/robot base
./bin/robot check chassis
./bin/robot base-test --rotate-only
```

正式命令链是：

```text
/cmd_vel/{teleop,test,nav,research}
  -> robot_control
  -> /chassis/host_motion_command
  -> stm32_bridge
  -> Upper v3 firmware
```

仓库不存在生产 `/cmd_vel/driver` 接口。Bridge 未进入当前 session 的
`WIRE_REARM_READY`、兼容门未允许或 Host 未完成 quiet→fresh intent 时，enable 会被
拒绝；不得绕过这些门。

## 4. 建图

Gate D 前只使用 Fake Base 或有人看护的标定流程。wheel-only 是当前默认：

```bash
./bin/robot mapping lidar quality --manual --fake-base --rviz
./bin/robot save-map my_map
```

完成 HIL 和几何标定后，受控实车命令为：

```bash
./bin/robot mapping lidar quality --manual --real-base --rviz
```

`precision` 与 `fast` 是实验 overlay。旧自动 frontier explorer 已移到
`experiments/legacy`，`auto_mapping_drive` 会被 bringup 拒绝。

## 5. 导航

导航要求 `base_mode:=real|fake` 和有效地图；`base_mode:=none` 会拒绝启动。

```bash
./bin/robot navigation /path/to/map.yaml --fake-base --rviz
```

完成 Gate D 后的受控实车路径：

```bash
./bin/robot navigation /path/to/map.yaml --real-base --rviz
```

在 RViz 中先执行 `2D Pose Estimate`，确认 scan 与地图重合，再发送
`2D Goal Pose`。`--localization-only` / `--nav2-only` 只用于现场回退。

`--ekf-base` 是 wheel+IMU 实验 alias，不是推荐默认；只有独立 Bag 证明优于
wheel-only、IMU 停止降级和 TF 唯一性通过后才可用于正式验收。

## 6. 启动后的事实

- Real/Fake provider 发布 Observation、链路和固件状态，不发布 odom/TF。
- `wheel_odometry` 发布 `/wheel/odom`，`imu_adapter` 发布 `/imu/data`。
- `formal_odometry` 在兼容门和当前 session 新鲜证据允许时发布 `/odom` 与
  `odom -> base_link`。
- wheel+IMU 模式的 EKF 只发布 `/odometry/filtered_internal`。
- `navigation_guard` 是公共 `/navigate_to_pose` Action 服务端，后端 Nav2 Action 为
  `/nav2/navigate_to_pose`。

## 7. 验证与排障

```bash
./bin/robot check lidar
./bin/robot check chassis
./bin/robot check tf
./bin/robot check mapping --allow-headless
./bin/robot check navigation
./bin/robot doctor
```

任何实车报告必须记录 upper/firmware commit、硬件 revision、参数 CRC、effective
config SHA-256、artifact SHA-256、标定版本和测量指标。详见
[Verification](../verification/README.md) 与 [rc2 发布说明](./releases/v0.6.0-rc2.md)。
