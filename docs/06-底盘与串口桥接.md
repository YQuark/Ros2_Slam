# 底盘与串口桥接

本文档描述 `stm32_robot_bridge` 的运行行为。协议字段以 [04-串口桥接协议](./04-串口桥接协议.md) 和下位机源码为准。

## 1. 职责

`stm32_robot_bridge` 只负责上位机与 STM32 底盘之间的桥接：

- 订阅 `/cmd_vel`。
- 发送 v2 `SET_VELOCITY` 控制帧。
- 被动接收 STM32 每 50ms 主动上报的 v2 `STATUS`。
- 发布 `/odom`、`/tf`、`/chassis/status`、`/battery_state` 和左右侧聚合电流。

当前 v2 STATUS 不含 IMU，bridge 不发布伪造 IMU 数据。

## 2. 启动入口

```bash
./robot.sh base
./robot.sh base --port /dev/serial0
./robot.sh mapping lidar --manual --real-base
./robot.sh navigation --real-base --map classroom_v1
```

默认底盘串口为 `/dev/serial0`。如临时接 USB-UART，可显式传入其他端口，但正式默认不自动扫描 USB 串口。

## 3. 代码结构

核心文件：

- `src/stm32_robot_bridge/stm32_robot_bridge/protocol_v2.py`: 纯协议实现与可测试聚合逻辑。
- `src/stm32_robot_bridge/stm32_robot_bridge/bridge_node.py`: ROS2 节点、串口读写、话题与服务。
- `launch_scripts/detect_base_port.sh`: 默认检查 `/dev/serial0`，`--probe` 时被动等待 v2 STATUS。
- `launch_scripts/check_chassis.sh`: GPIO UART、权限和 v2 STATUS 诊断。

## 4. 串口管理

启动后：

1. 打开 `port`，默认 `/dev/serial0`，115200 8N1。
2. DTR/RTS 尽量拉低，避免 USB 串口场景误复位。
3. 清空串口缓冲。
4. 发送 2~3 次 `SET_VELOCITY(linear=0, angular=0, enable=0)`，释放旧上位机控制源。
5. 只读取下位机主动 STATUS，不发送状态请求。

串口读写异常时关闭串口并按 `serial_open_retry_sec` 重试；关闭、退出或重连前尽力发送一次 `enable=0`。

## 5. 控制源释放策略

`/cmd_vel` 有效期内：

- 按 `control_hz` 和 `drive_keepalive_sec` 发送 `SET_VELOCITY(enable=1)`。
- 速度可以为零；只要命令仍新鲜，就允许保持 upper 控制源。

`/cmd_vel` 超时后：

- 只发送一次 `SET_VELOCITY(linear=0, angular=0, enable=0)`。
- 发送成功后标记 upper 控制源已释放。
- 后续不再周期发送零速度控制帧，允许 PS2、ESP12F 或巡线接管。

急停不等于停车。急停只通过 `/chassis/estop` 显式发送：

```bash
ros2 service call /chassis/estop std_srvs/srv/SetBool "{data: true}"
ros2 service call /chassis/estop std_srvs/srv/SetBool "{data: false}"
```

## 6. STATUS 处理

bridge 只接受固定 64B、version=2 的 STATUS。其他长度或版本直接丢弃并限频告警。

接收后完成单位换算：

- `battery_mv` -> V。
- `motor_speed_mmps[]` -> m/s。
- `motor_current_ma[]` -> A。
- `motor_target_mmps[]` -> m/s。
- `motor_output_permille[]` 保持 permille。

状态日志摘要包含 protocol、control_source、status_flags、enabled mask、speed-valid mask、电池、电流、当前错误和锁存错误。

## 7. 四路聚合与 odom

当前默认两驱布局为 M2 左、M3 右，但 bridge 不写死该布局：

- 左侧: `enabled_mask & 0b0011`。
- 右侧: `enabled_mask & 0b1100`。
- 每侧速度和目标速度取已启用电机平均值。
- 每侧编码器取已启用电机平均值，仅诊断展示。
- 每侧电流求和。

任一侧无启用电机，或任一已启用电机速度无效，本帧 odom 不可信。急停或 fault-stop 标志置位时，bridge 也不会把当前运动数据作为可信 odom。

里程计速度：

```text
vx = (left_speed + right_speed) / 2
wz = (right_speed - left_speed) / wheel_track_width
```

默认 `wheel_track_width=0.1780`，`wheel_radius=0.0350`。

## 8. TF 与 EKF

- 不启用 EKF：bridge 发布 `odom -> base_link`。
- 启用 wheel-only EKF：bridge 不发布 TF，EKF 使用 `/odom` 发布 `odom -> base_link`。

在没有独立 IMU 协议前，EKF 不配置 IMU 输入。

## 9. 故障排查

| 现象 | 排查方向 |
|------|----------|
| `/dev/serial0` 不存在 | 检查树莓派 UART 是否启用，确认 `/dev/serial0 -> /dev/ttyAMA0` |
| 串口权限不足 | `sudo usermod -aG dialout $USER` 后重新登录 |
| 1 秒内无 v2 STATUS | 检查 STM32 上电、PD8/PD9 接线、共地和 115200 8N1 |
| `/odom` 不更新 | 看 `status_summary` 是否出现，确认 STATUS version=2 且 payload=64B |
| `/cmd_vel` 后 PS2 不能接管 | 确认超时后日志出现 `enable=0` 释放控制源 |
| 急停后 odom 不可信 | 这是预期行为；解除急停需显式调用 `/chassis/estop` 传 `false` |
